# Аккаунты и онбординг CRAFT

## Продуктовое решение
CRAFT — account-first платформа. Человек создаёт личный аккаунт до выбора программы. Регистрация бесплатна и не означает покупку или зачисление на платное обучение.

## Первый сценарий
1. Пользователь изучает публичные каталоги без входа.
2. Создаёт аккаунт по имени, email и паролю.
3. Подтверждает email, если это включено в настройках Supabase Auth.
4. Попадает в личный кабинет.
5. Выбирает направление или бизнес-концепцию.
6. Создаёт проект, сохраняет гипотезы и возвращается к ним позже.
7. Доступ к учебной программе появляется отдельно после ручного зачисления или подтверждённой оплаты.

## Техническая основа
- Supabase Auth управляет учётными данными, сессиями, подтверждением email и восстановлением доступа.
- Next.js server actions выполняют регистрацию, вход и выход.
- Supabase SSR поддерживает сессии на сервере.
- Middleware обновляет сессию и перенаправляет неавторизованных пользователей с /dashboard.
- Row Level Security ограничивает чтение и изменение проектов их владельцами.
- Секретный service-role ключ не используется в браузере и не нужен для базового пользовательского сценария.

## Переменные окружения
Скопировать .env.example в .env.local и заполнить:
- NEXT_PUBLIC_SITE_URL
- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_ANON_KEY

В Supabase Auth нужно настроить Site URL и Redirect URL для локальной и production-среды. Для production использовать HTTPS и настроить SMTP-провайдера.

## База данных
supabase/schema.sql создаёт профили и ученические проекты, включая RLS-политики. Запустить SQL в Supabase SQL Editor после создания проекта.

## Важно
В репозитории подготовлена интеграция, но аккаунты не будут работать до подключения Supabase и применения SQL-схемы. Не добавлять реальные ключи в Git. Перед публичным запуском проверить email confirmation, восстановление доступа, rate limits, SMTP, юридические документы и критические пользовательские сценарии.
