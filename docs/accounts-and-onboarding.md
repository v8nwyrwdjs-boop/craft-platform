# Аккаунты, проекты и обучение CRAFT

## Продуктовое решение
CRAFT — account-first платформа. Пользователь может изучать публичные каталоги и бесплатно зарегистрировать аккаунт. Регистрация не является покупкой и не открывает платную программу автоматически.

## Пользовательский путь
1. Изучить направления и бизнес-концепции без входа.
2. Создать аккаунт по имени, email и паролю.
3. Подтвердить email через Supabase Auth.
4. Войти в личный кабинет.
5. Создать свой проект или сохранить выбранную концепцию/направление.
6. Получить зачисление в программу отдельно.
7. Открыть учебные модули, отмечать уроки и отслеживать прогресс.
8. В будущих итерациях отправлять задания и получать обратную связь наставника.

## Техническая основа
- Supabase Auth управляет учётными данными, сессиями и восстановлением доступа.
- Next.js server actions выполняют регистрацию, вход, выход, сброс пароля и создание проектов.
- Supabase SSR поддерживает сессии на сервере.
- Middleware обновляет сессию и защищает /dashboard.
- RLS ограничивает доступ к проектам, зачислениям и прогрессу владельцем.
- /learn/[module] дополнительно проверяет активное зачисление на сервере.
- Сервисный ключ не нужен для клиентских сценариев и не должен попадать в браузер.

## Переменные окружения
Скопировать .env.example в .env.local:
- NEXT_PUBLIC_SITE_URL
- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_ANON_KEY

В Supabase Auth настроить Site URL и Redirect URLs для локальной и production-среды. Для production настроить собственный SMTP и HTTPS.

## Схема данных
Применить supabase/schema.sql:
- profiles — профиль.
- student_projects — проекты и выбранные элементы каталога.
- enrollments — ручное зачисление в программу.
- lesson_progress — статусы уроков.
- assignment_submissions — текстовые ответы ученика на практические задания.
- mentor_feedback — записи обратной связи, доступные ученику для чтения.

Зачисление создаётся администратором через защищённый Supabase Dashboard или отдельную будущую admin-панель. Не выдавать обычным пользователям права insert/update на enrollments.

## Что реализовано в коде
- Регистрация, вход, выход.
- Email callback.
- Запрос восстановления пароля и установка нового пароля.
- Личный кабинет с созданием собственного проекта.
- Детальные страницы концепций и направлений с сохранением в проекты.
- Каталог программы, серверная проверка зачисления, отметка завершения урока.
- Отправка текстовых ответов на практические задания с проверкой активного зачисления.
- Таблица обратной связи наставника с доступом ученика только к собственным комментариям.
- RLS-политики для пользовательских данных.

## Ограничения до запуска
Supabase не подключён к реальному проекту, поэтому живые регистрации и БД пока не работают. Нужны env-переменные, redirect URL, SMTP и применение SQL. Нужна проверка сборки, сценариев регистрации/сброса пароля, RLS и мобильного интерфейса. Учебные материалы — стартовый контент, не финальная методология. Перед публичным запуском подготовить privacy policy, terms, согласия и процедуру обработки запросов субъектов данных.

## Ручное тестовое зачисление
После регистрации тестового пользователя можно выдать ему доступ через Supabase SQL Editor. Используй email только тестового аккаунта, который контролируешь:

\`\`\`sql
insert into public.enrollments (student_id, program_slug, status)
select id, 'craft-foundation', 'active'
from auth.users
where email = 'test@example.com'
on conflict (student_id, program_slug)
do update set status = 'active';
\`\`\`

Обычный пользователь не может самостоятельно создавать или менять записи enrollments. Для реальной работы зачисление должно выполняться только сотрудником через защищённую админ-панель или серверный backend.
