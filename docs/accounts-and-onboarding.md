# Аккаунты, проекты и обучение CRAFT

## Продуктовая модель

CRAFT — account-first платформа. Публичные каталоги доступны без входа; аккаунт можно создать бесплатно. Регистрация сама по себе не является покупкой и не открывает платную программу.

## Пользовательский путь

1. Изучить направления и бизнес-концепции.
2. Создать аккаунт по имени, email и паролю.
3. Подтвердить email через Supabase Auth (если включено подтверждение).
4. Войти в личный кабинет.
5. Создать собственный проект или сохранить концепцию/направление.
6. Получить отдельное зачисление в программу.
7. Открыть учебные модули, отмечать уроки и отслеживать прогресс.
8. Отправлять текстовые задания и получать обратную связь наставника.

## Техническая основа

- Supabase Auth управляет учётными данными, сессиями и восстановлением доступа.
- Next.js server actions выполняют регистрацию, вход, выход, сброс пароля и запись проектов.
- Supabase SSR поддерживает сессии на сервере.
- `proxy.ts` обновляет сессию и защищает маршрут `/dashboard`.
- Серверные страницы и actions повторно проверяют пользователя и зачисление.
- RLS ограничивает доступ к данным на уровне PostgreSQL.
- Сервисный ключ не нужен для клиентских сценариев и не должен попадать в браузер.

## Переменные окружения

Скопировать `.env.example` в `.env.local`:

- `NEXT_PUBLIC_SITE_URL`
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

Vercel project имеет настроенные Supabase URL и publishable key в средах проекта. Это подтверждает наличие конфигурации окружения, но не является доказательством успешного end-to-end сценария или актуальности схемы БД. Для production необходимо подтвердить redirect URLs, SMTP, SQL schema и миграции.

## Схема данных

Применить `supabase/schema.sql`, затем проверить и применить все файлы из `supabase/migrations/`:

- `profiles` — профиль.
- `student_projects` — проекты и выбранные элементы каталога.
- `enrollments` — ручное зачисление в программу.
- `lesson_progress` — статусы уроков.
- `assignment_submissions` — текстовые ответы ученика.
- `mentor_feedback` — обратная связь, доступная ученику для чтения.

Не выдавать обычным пользователям права insert/update на `enrollments`.

## Роли команды

- Внутренняя панель находится по адресу `/admin`.
- Доступ определяется только доверенным `app_metadata.role`: `admin` или `mentor`.
- Нельзя назначать роль через `user_metadata` или пользовательскую форму.
- Назначать роль можно только из доверенного Supabase Admin API / защищённой административной среды.
- Admin может активировать зачисление; admin и mentor могут просматривать отправки, менять статус и отправлять обратную связь.
- RLS повторно проверяет права в базе данных.

## Что реализовано в коде

- Регистрация, вход и выход.
- Email callback и запрос восстановления пароля.
- Личный кабинет и создание проектов.
- Сохранение концепций и направлений в проекты.
- Учебный каталог и серверная проверка активного зачисления.
- Сохранение прогресса уроков.
- Отправка текстовых заданий.
- Просмотр учеником собственной обратной связи.
- Базовая внутренняя панель наставника/администратора.

## Что необходимо проверить до запуска

- E2E регистрация, подтверждение email, вход, выход и сброс пароля на Preview с реальным тестовым аккаунтом.
- Фактическое применение schema.sql и всех миграций к целевому Supabase project.
- RLS для ролей student, mentor и admin с разными тестовыми аккаунтами.
- Доставку писем через настроенный SMTP.
- Мобильные сценарии на физических устройствах.
- Полноту методических материалов, критерии проверки и операционный процесс обратной связи.
- Политику конфиденциальности, условия использования и необходимые согласия после правовой проверки.

Платежи, автоматические зачисления, уведомления, вложения и полноценная CRM пока не реализованы.

## Ручное тестовое зачисление

После регистрации тестового пользователя можно выдать доступ через Supabase SQL Editor. Используй только email тестового аккаунта, который контролируешь:

```sql
insert into public.enrollments (student_id, program_slug, status)
select id, 'craft-foundation', 'active'
from auth.users
where email = 'test@example.com'
on conflict (student_id, program_slug)
do update set status = 'active';
```

Обычный пользователь не может самостоятельно создавать или менять записи enrollments.
