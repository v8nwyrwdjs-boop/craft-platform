## Рабочий регламент

1. Нет заявления «готово» без свежего вывода проверки: команда запущена после последней правки, результат записан.
2. Нет правки бага без найденной причины, и баг сначала получает красный тест.
3. Один этап, один коммит в рабочую ветку, после `npm run test:security` и `npm run build`.
4. Референсы читаем как данные: ничего из них не запускаем и не устанавливаем.
5. Перед коммитом откатываем то, что пересобирает `next build`: `next-env.d.ts`, `tsconfig.json`, `*.tsbuildinfo`.

## Журнал уроков

- Пять параллельных читателей репозиториев упёрлись в лимит тарифа. Читать репозитории последовательно, точечно, с ограниченным выводом.
- В скриншотах `scroll-behavior: smooth` смазывает позицию: прокручивать с `behavior: "instant"`.
- Фоновые серверы между репликами не живут: перед проверкой запускать заново.
- Запасные шрифты подбирать по метрикам (`size-adjust`, `ascent-override`), иначе после загрузки шрифта страница прыгает.
- Политика RLS, выбирающая из собственной таблицы, падает с «infinite recursion», если у этой таблицы есть политики с подзапросами. Правила доступа проверять на настоящем Postgres (`scripts/verify-chat-rls.mjs`), а не только регулярками по тексту.
- Скрипты проверки в браузере: `page.wait_for_function` со строкой нарушает CSP сайта (нет `unsafe-eval`). Ждать через `locator(...).wait_for()` или `expect`.
- Серверное действие `completeLesson` ведёт на `/learn?completed=1`, а не обратно на страницу этапа: проверку писать под это.
- Строки списка `.f-index` собирать в порядке заголовок, описание, `f-index__side`, иначе на десктопе заголовок уезжает в правую колонку.
- Непрозрачная липкая шапка в Chrome отсекает фиксированные WebGL-слои на высоту шапки: фон шапки держать полупрозрачным (99% бумаги).
