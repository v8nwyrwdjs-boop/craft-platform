# CRAFT — школа создания цифровых продуктов

CRAFT помогает пройти путь от идеи до собственного цифрового продукта: разобраться в технологиях, проверить проблему и спрос, собрать первую версию и улучшать её на основе обратной связи.

## Состояние проекта

Проект развивается в отдельной ветке `craft/visual-excellence` и проверяется через Vercel Preview. Production и ветка `main` не являются частью текущего рабочего цикла.

**Сейчас реализовано:** публичный сайт и каталоги, форматы участия, регистрация и вход через Supabase Auth, личный кабинет, проекты ученика, учебный маршрут, прогресс, отправка текстовых заданий и базовая панель наставника/администратора.

**До публичного запуска остаются:** реальное end-to-end тестирование Auth и RLS, подтверждение применения SQL-схемы и миграций, настройка и проверка SMTP, полноценная редактура учебной программы, проверка мобильных сценариев на физических устройствах, юридические документы и коммерческая инфраструктура. Платежи не реализованы.

## Локальный запуск

Нужен Node.js 24.

1. Установить зависимости: `npm install`.
2. Скопировать `.env.example` в `.env.local`.
3. Заполнить переменные:
   - `NEXT_PUBLIC_SITE_URL` — доверенный HTTPS origin для production; локально `http://localhost:3000`.
   - `NEXT_PUBLIC_SUPABASE_URL` — URL Supabase project.
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — publishable key проекта.
4. Запустить `npm run dev`.

Перед production необходимо настроить в Supabase Auth Site URL, redirect URLs и SMTP. Не помещать secret/service-role key в клиентский код или публичные переменные окружения.

## Основные маршруты

- `/` — главная.
- `/directions` и `/directions/[slug]` — направления и их описание.
- `/products` и `/products/[id]` — библиотека бизнес-концепций.
- `/formats` — предварительные форматы участия и цены.
- `/register`, `/login`, `/forgot-password` — аккаунт и восстановление доступа.
- `/dashboard` — проекты и личный кабинет.
- `/learn`, `/learn/[module]` — учебная программа и задания (при активном зачислении).
- `/admin` — внутренняя панель для ролей admin и mentor.

## Данные и доступ

Основная схема находится в `supabase/schema.sql`. Дополнительные изменения БД — в `supabase/migrations/`; их необходимо применять в Supabase отдельно и проверять на целевом проекте.

- `profiles` — профиль.
- `student_projects` — проекты ученика.
- `enrollments` — доступ к программе.
- `lesson_progress` — прогресс.
- `assignment_submissions` — практические ответы.
- `mentor_feedback` — обратная связь.

RLS ограничивает пользовательские записи владельцем. Роли команды проверяются через доверенный `app_metadata.role` (`admin` или `mentor`), а не через пользовательские метаданные. Обычный пользователь не может самостоятельно выдать себе зачисление.

## Принципы

- Каталоги помогают выбрать направление или гипотезу, но не обещают прибыль.
- Сначала проблема, аудитория и проверка спроса — затем разработка.
- Обучение с наставником и разработка под ключ — разные услуги.
- Не публиковать неподтверждённые отзывы, кейсы, сроки ответа и гарантии.
- Не включать платежи, подписки или production-релиз до проверки операционных и юридических условий.
